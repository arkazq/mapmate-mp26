# 경로 중심 UI/UX 개선

## 참고와 적용

2026-10-02~03에 [네이버지도 모바일 웹](https://m.map.naver.com/)의 지도/빠른길찾기와 [카카오맵 모바일 길찾기](https://m.map.kakao.com/actions/routeView)의 서울역→숭실대학교 대중교통 결과를 실제로 확인했습니다. 네이티브 지도 앱을 복제하거나 지도 SDK를 새로 붙인 작업은 아닙니다.

- 출발·도착을 한 묶음으로 표시하고 장소명과 시각을 분리합니다.
- 실제 경로 구간을 도보·버스·지하철 색과 아이콘, 소요시간 비율 막대로 보여줍니다.
- 긴 설명 대신 첫 버스 도착 시간, 정류장 접근 시간, 탑승 여유를 분리합니다.
- 사용자가 경로를 읽는 중에도 이동 시작 동작에 접근할 수 있도록 하단에 고정합니다.

## 화면 변경

| 화면 | 변경 |
|---|---|
| 홈 | 출발/도착 묶음, 권장 출발과 목표 도착 시각, 구간 요약, 첫 탑승 도착정보, 하단 상세/시작 동작 |
| 상세 경로 | 이동 경로/탑승·출발 탭, 연결된 승하차 타임라인, 대안 비교, 펼쳐 보는 계산 근거, 고정 시작 버튼 |
| 루틴 목록 | 동일한 출발/도착 표현, 반복 요일과 다음 출발, 상단 수정과 하단 경로/삭제 동작 |
| 등록 장소 | 출발·도착 아이콘 및 선택 완료 표시, 주소/장소 검색 입력 문구 정리 |
| 구간 측정 | 구간 진행 표시, 현재 구간과 경과 시간 강조, 전체 완료 전 도착 버튼은 보조 동작으로 구분 |

큰 글자에서는 홈의 날짜와 주요 버튼을 세로로 배치합니다. 장소명은 잘라내지 않고 줄바꿈하며 대안의 상태/소요시간도 필요하면 다음 줄에 표시합니다. 버스는 파랑, 지하철은 초록, 대기는 황갈색, 도보는 중립색으로 구분하고 색만으로 정보를 전달하지 않습니다. 구간 색은 노선 고유색을 뜻하지 않습니다.

## 데이터와 동작 원칙

- 막대와 경로 순서는 선택된 `routeSegments`의 `segmentIndex`, 기본 예상 시간에서 가져옵니다. 지리 경로나 정류장 위치를 새로 추정하지 않습니다.
- 전체 예상 시간은 기존 보정 결과, 개별 구간 표시는 저장된 `plannedDurationMinutes`입니다. 개인 보정에 따라 두 값의 합은 다를 수 있습니다.
- 실시간 값이 없으면 도착 숫자를 만들지 않습니다. 첫 버스가 없는 경로에는 가짜 버스 항목 대신 정보 없음 상태를 표시합니다.
- 구간이 없으면 기존 전체 이동 예상과 기본 경로 표현을 유지합니다.
- 당일 완료/다음 날 출발에는 새 측정 시작 버튼을 표시하지 않습니다. 진행 중 측정은 기존 이어하기 경로를 사용합니다.
- 기존 추천 계산, 후보 선택, 알림 예약, 데이터 저장 정책은 이번 화면 개선에서 변경하지 않았습니다.

## 구현과 재검증

- 공통 표현: `presentation/common/RouteJourney.kt`
- 도착정보: `presentation/common/RouteBoardingAdviceCards.kt`
- 화면 검사: `MapMateVisualTest`, 이동/편집/복귀: `MapMateNavigationTest`
- 상태: 정상, 빈 화면, 오류/재시도, 실시간 없음, 지하철 전용, 복수 환승, 오늘 완료/다음 출발, 진행 중 측정.
- 크기/테마: 일반 밝은 화면, 어두운 화면, 320dp와 360dp 폭, 1.5~2배 글자.
- 실행: `testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug`, 전용 에뮬레이터에서 계측 검사.

### 최종 확인 결과

- 마지막 홈/상세 테마 수정 후 단위 테스트 237개(51개 테스트 클래스), 디버그 앱/테스트 APK 빌드가 통과했습니다.
- `lintDebug`는 오류 없이 완료했습니다. 기존 경고 38개와 힌트 1개는 남아 있습니다.
- Pixel 8 에뮬레이터 계측 검사 70개가 통과했습니다. 화면 검사 19개, 내비게이션 검사 8개, 구간 수정 UI 검사 4개가 포함됩니다.
- 실제 최종 캡처에서 밝은/어두운 홈, 320dp/2배 글자, 상세 타임라인/대안, 측정 중, 오늘 완료, 오류/재시도, 실시간 정보 없음 상태를 확인했습니다.
- 화면 테스트는 실제 구간의 환승/도보 합계, 탭 전환, 계산 근거 펼치기, 수정/시작 동작, 순서대로 구간 완료, 완료 후 새 측정 버튼 숨김을 검사합니다.
- `git diff --check`가 통과했습니다. UI 개선 검증 당시에는 미커밋 작업 트리였으며, 커밋/푸시는 이후 단계에서 진행합니다.

계측 실행에서는 별도 프로세스 재시작용 `TrackingRestartTest`를 제외했습니다. 이번 UI 검증 결과를 앱 강제 종료/재시작 검증까지 확장해서 해석하지 않습니다.

실제 API가 아닌 테스트 응답과 오프라인 Pixel 8 에뮬레이터를 사용합니다. 이 검사는 실기기 OEM 알림 전달, 실제 이동이나 API 최신성 검증을 대신하지 않습니다.

### 추가 실행 검증

2026-10-03에 Android Studio MCP를 설치·연결하고 IDE 분석과 빌드를 수행했습니다. 런타임 검사는 MCP 명령 실행 승인 대기로 ADB/Gradle에서 별도로 수행했습니다.

- IDE 빌드는 성공했고, 홈/상세/측정 화면 분석에서는 오류 없이 경고 15개가 보고됐습니다.
- 단위 테스트 237개를 캐시 재사용 없이 다시 실행해 통과했습니다. 디버그 앱과 테스트 APK 빌드도 성공했습니다.
- 일반 계측 검사 70개가 다시 통과했습니다.
- `TrackingRestartTest`의 세 메서드를 각각 별도 프로세스에서 실행하고 중간에 앱을 강제 종료했습니다. 진행 중 구간 복원, 완료 기록 저장, 다시 재시작한 뒤 완료 이벤트 제외 및 중복 측정 차단이 모두 통과했습니다.
- 실제 기본 앱 실행에서도 루틴 수정 버튼 한 번으로 수정 화면에 진입했고, 재실행 후 홈의 오늘 이동 완료와 다음 출발 표시가 유지됐습니다.
- 새 스크린샷 32개를 확보하고 대표 화면을 직접 확인했습니다. 검사 후 크래시 로그는 비어 있었습니다.

추가 검증 역시 오프라인 에뮬레이터와 테스트 경로 응답을 사용했습니다. 실제 버스 API 조회 및 실물 기기의 알림 발화는 포함하지 않았습니다.

지하철 아이콘은 Google Material Icons `train`을 Android VectorDrawable로 변환했습니다. 원문 출처는 drawable 주석, Apache 2.0 라이선스는 APK의 `assets/licenses/material-icons-LICENSE.txt`에 포함합니다.
